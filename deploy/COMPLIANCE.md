## 四、数据备份与异地容灾

- **本地备份**：`postgres-backup` 容器，@daily 全量 gzip dump，保留 14 日/8 周/6 月/2 年
- **MinIO 对象备份**：⬜ 目前未纳入备份；建议 `mc mirror` 到异地 OSS
- **异地同步**：⬜ 待配置 rclone + crontab → 阿里云 OSS / 腾讯云 COS
- **RPO / RTO 目标**：
  - RPO ≤ 24h（每日全量）
  - RTO ≤ 4h（单节点重新拉起 + 还原最近一次全量）
- **每季度演练**：⬜ 需制定"还原演练表"，季度执行一次

## 五、安全事件应急预案（Runbook 骨架）

### 5.1 账号泄露
1. 立即 `docker compose exec backend python3 scripts/revoke_sessions.py --user=<id>`（⬜ 脚本待编写）
2. 强制该账号重置密码
3. 审计日志回溯：看 `audit_logs` 中该 user_id 最近 30 天所有写操作
4. 通知用户本人（邮件 / 短信模板待写）

### 5.2 数据库异常/损坏
1. `docker compose stop backend`
2. 定位最近一次完好备份：`docker compose exec postgres-backup ls -lh /backups/daily`
3. 按 README "从备份恢复" 流程恢复
4. 启动 backend 后跑一次 `scripts/verify_data_integrity.py`（⬜ 脚本待编写）

### 5.3 凭据泄露（JWT_SECRET / DB_PASSWORD / S3_SECRET_KEY）
1. 修改 `.env`，生成新密钥：`openssl rand -hex 48`
2. `docker compose up -d --force-recreate backend`（JWT 秘钥轮换会让全部用户登出）
3. `docker compose restart postgres minio`（如涉及 DB/S3 密钥）
4. 审计日志留档 + 通知监管（若属金融 IT 监管事件）

### 5.4 勒索/恶意删除
1. 断开服务器公网（阿里云控制台释放公网 IP 或改安全组）
2. 备份当前磁盘快照留证
3. 从异地备份回滚（见 §四）
4. 溯源 + 提交属地网安

## 七、与甲方签署的 DPA（数据处理协议）模板要点

供客户谈判时参考，不替代律师审阅：

1. **双方身份**：甲方=数据控制者，乙方=受托处理者
2. **处理目的**：仅用于"资产包定价估算与库存决策沙盘"，不得用于其他目的
3. **处理数据范围**：车型、VIN、上牌日期、里程、债权金额；**不收集** 债务人身份证号、联系方式（除非甲方主动提供并单独授权）
4. **保存期限**：甲方主动删除 or 合作终止后 30 日内；备份另存 180 日
5. **安全措施**：本文档 §一、§二 所列控制
6. **子处理者清单**：§三所列，任何变更 10 日前书面通知甲方
7. **跨境传输**：默认境内；如用境外 LLM 节点，单独书面同意
8. **事件通知**：72 小时内通知甲方安全事件
9. **审计权**：甲方每年可要求一次现场或远程审计
10. **终止与返还**：合作终止后 7 日内返还或销毁全部数据，出具销毁证明
